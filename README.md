# RDP Launcher

Минимальный интерфейс к **официальному клиенту FreeRDP**. Не рисует RDP сам,
не линкуется с `libfreerdp` и не изобретает протокол — он собирает командную строку
и запускает `sdl-freerdp` отдельным процессом.

> **English:** a minimal GTK4/libadwaita front-end for the official FreeRDP client.
> Instead of embedding `libfreerdp` (the approach Remmina, KRDC and GNOME Connections take),
> it builds a command line and launches `sdl-freerdp` — the current SDL3 client that runs
> natively on Wayland — as a separate process. Benefits: no XWayland blur, crash isolation,
> no ABI coupling to FreeRDP, several sessions at once. Profiles, display/audio/drive
> settings, GNOME keyring for passwords, `.rdp` import/export.
> **Note:** the UI strings are currently Russian-only; localisation is the main missing piece
> for wider use (patches welcome in `rdp_launcher/options.py` and `rdp_launcher/ui/`).
> See [`docs/research.md`](docs/research.md) for the reasoning and the measurements behind it.

## Зачем именно так

Разбор существующего софта (подробности — в [`docs/research.md`](docs/research.md)) показал,
что по 96 разобранным тикетам GUI-обвязка виновата в **20** случаях против **14** у ядра FreeRDP.
Remmina, KRDC и GNOME Connections встраивают библиотеку, чтобы получить RDP внутри своего окна, —
и вместе с картинкой забирают себе рендеринг, ввод и работу с мониторами, то есть ровно ту зону,
где живут баги (например, Remmina пишет в `MonitorDefArray` FreeRDP и падает на двух мониторах).


Лаунчер выбирает обратный подход: **вся отрисовка остаётся у официального SDL3-клиента**,
а наше дело — профили, настройки и запуск.

Следствия:

* нет наследования класса багов обвязки;
* изоляция падений — клиент умер, лаунчер жив;
* нет связи с ABI FreeRDP: работает с любой версией в дистрибутиве, `-devel` не нужен;
* несколько сессий одновременно — бесплатно, каждая своим окном.

## Требования

| Компонент | Зачем | Проверка |
|---|---|---|
| `freerdp` | клиенты `sdl-freerdp`, `xfreerdp`, `wlfreerdp` | `command -v sdl-freerdp` |
| `python3-gobject`, `gtk4`, `libadwaita` | интерфейс | `python3 -c "import gi; gi.require_version('Adw','1')"` |
| `libsecret` | хранение пароля в связке ключей GNOME | `command -v secret-tool` |

На Fedora 44 всё это уже стоит; для полного набора:

```bash
sudo dnf install freerdp python3-gobject gtk4 libadwaita libsecret
```

## Установка

```bash
./install.sh                 # ярлык в меню, иконка, связка .rdp-файлов
./install.sh --uninstall     # удалить
```

Скрипт сам проверяет зависимости и кладёт всё в `~/.local/share` (root не нужен).

Запуск без установки:

```bash
PYTHONPATH=$PWD python3 -m rdp_launcher
```

## Что в интерфейсе

Главное окно — список профилей. Подключение: клик по строке или кнопка ▶.
Меню строки: изменить, дублировать, экспорт в `.rdp`, удалить.

Диалог профиля строится **целиком из реестра опций**, поэтому интерфейс и командная строка
не могут разойтись:

| Группа | Что настраивается |
|---|---|
| Основное | название, адрес, порт, пользователь, домен, пароль |
| Экран | полный экран, подстройка разрешения под окно, размер окна, все мониторы |
| Звук | вывод (здесь / на сервере / выключен), качество, микрофон |
| Диски и файлы | общий буфер обмена, сетевые диски, принтеры |
| Дополнительно | проверка сертификата, профиль сети, GFX и обход чёрного окна, раскладка клавиатуры, сжатие, отключение обоев/тем/анимаций, авто-переподключение |

Пароль хранится в **связке ключей GNOME** (libsecret) и никогда не попадает ни в файл профиля,
ни в командную строку: он передаётся клиенту через stdin (`/from-stdin`), поэтому его не видно
в списке процессов. Если пароль не сохранён, клиент спросит его сам.

## Как добавить настройку

Одна запись в `rdp_launcher/options.py` описывает сразу три вещи: поле интерфейса,
флаг FreeRDP и ключ `.rdp`. Пример:

```python
Option(
    key="span",                       # ключ в профиле
    label="Растянуть на все мониторы", # подпись в интерфейсе
    group=GROUP_SCREEN,
    default=False,
    cli_on=("+span",),                # что добавить в командную строку
    rdp_on=(("span monitors", "i:1"),),  # что записать в .rdp
    rdp_off=(("span monitors", "i:0"),),
    hint="Только для одинаковых разрешений.",
),
```

Всё остальное — форма, сборка `argv`, экспорт в `.rdp` — произойдёт само.
Новый флаг будет проверен тестом на живом клиенте (см. ниже).

## Тесты

```bash
python3 tests/test_core.py    # 28 тестов логики, GTK не требуется
python3 tests/smoke_gui.py    # сборка окна и диалога, имитация сохранения
```

Отдельно стоит упомянуть `test_every_registry_flag_is_accepted`: он **эмпирически** проверяет
каждый флаг реестра на настоящем клиенте (клиент печатает «Unexpected keyword» на незнакомый
аргумент) и содержит контрольный тест на заведомо мусорный флаг. Именно этот тест нашёл,
что `/camera` и `/audio-quality` в FreeRDP 3.31 не существуют: камеры нет вовсе, а качество
звука — под-опция `/sound:sys:pulse,quality:…`.

## Импорт и экспорт `.rdp`

Профиль экспортируется в формат Microsoft и импортируется обратно (меню → «Импорт из .rdp…»).
Файлы `.rdp` также связываются с приложением при установке, так что их можно открывать двойным
щелчком. Пароли в `.rdp` не пишутся.

## Стек интерфейса

**GTK 4 + libadwaita** через PyGObject (Python-биндинги). libadwaita — это и есть
дизайн-система GNOME, поэтому вид «как родное» получается не стилизацией, а по построению:
`Adw.ApplicationWindow`, `Adw.HeaderBar`, `Adw.PreferencesPage`/`Group`, `Adw.ActionRow`,
`Adw.SwitchRow`/`ComboRow`/`SpinRow`/`EntryRow`/`ExpanderRow`, `Adw.ToastOverlay`,
`Adw.StatusPage`, `Adw.Banner`, `Adw.Dialog`, `Adw.AboutDialog`, `Gtk.FileDialog`.
Цвета, скругления и акцентный цвет берутся из системной темы автоматически.

Проверить версии:

```bash
python3 -c "import gi; gi.require_version('Adw','1'); from gi.repository import Adw; print(Adw.MAJOR_VERSION, Adw.MINOR_VERSION)"
```

## Диагностика

### Буфер обмена приходит с `\uXXXX`

Симптом: при вставке в Windows кириллица выглядит как `\u0427\u0442\u043e…`.

Проверено на практике: **это не RDP и не лаунчер.** Скрипт
[`tools/check-clipboard.sh`](tools/check-clipboard.sh) читает буфер обмена Linux напрямую
(`wl-paste`) и в разобранном случае показал, что экранированный текст уже лежал в буфере
**до** подключения — то есть его таким записало приложение-источник (веб-интерфейсы и
Electron-приложения нередко кладут в буфер JSON-строку).

```bash
./tools/check-clipboard.sh             # что сейчас в буфере и есть ли \uXXXX
./tools/check-clipboard.sh --selftest  # положить контрольную строку и проверить её же
```

`--selftest` кладёт в буфер заведомо чистый UTF-8 и предлагает вставить его в Windows:
если чистая строка доходит правильно — клипборд RDP исправен.

### Звук отстаёт от картинки

RDP передаёт звук и видео независимыми потоками, поэтому небольшой рассинхрон — норма.
Уменьшить его можно буферизацией звука (`/sound:...,latency:<мс>`):

| Группа «Звук» → «Буферизация звука, мс» | Результат |
|---|---|
| `0` (по умолчанию) | как решит клиент |
| `100`–`150` | заметно меньше отставание, обычно без артефактов |
| `< 50` | почти без задержки, но возможны щелчки и прерывания |

Начать стоит со `100`. Полностью убрать рассинхрон нельзя: видео идёт своим конвейером
(RemoteFX/GFX), и его задержка задаётся сервером.

## Интерфейс внутри окна сессии

Короткий ответ: **свои виджеты в окно `sdl-freerdp` встроить нельзя**, и это осознанный выбор
архитектуры. Окно принадлежит отдельному процессу SDL, а на Wayland межпроцессного
встраивания не существует в принципе (в X11 был XEmbed, в Wayland аналога нет). Если бы мы
хотели UI внутри окна, пришлось бы встраивать `libfreerdp` в свой процесс — то есть вернуться
к архитектуре Remmina и получить обратно тот самый класс багов (атрибуция: обвязка 20 против 14 у ядра).

Что реально доступно:

| Способ | Что даёт | Ограничение |
|---|---|---|
| Встроенная панель FreeRDP `/floatbar` | готовая панель прямо в окне сессии | **Только X11-клиент.** Проверено `strings`: в `xfreerdp` 13 совпадений (`xf_floatbar.c`), в `sdl-freerdp` — **ноль**. С SDL это пустышка |
| `/action-script:<файл>` | свои горячие клавиши внутри сессии: комбинация вызывает ваш скрипт | UI рисует скрипт (например, отдельное окно), а не клиент |
| Глобальный хоткей GNOME + наша GTK-панель | панель управления сессией в стиле GNOME, доступная по клавишам | отдельное окно, а не панель внутри сессии |
| Встроить `libfreerdp`/IronRDP в свой процесс | любые виджеты внутри окна | переписывание рендеринга и ввода + возврат класса багов обвязки |

Штатные горячие клавиши `sdl-freerdp` уже работают без всякого UI:
`Ctrl+Alt+Enter` — полный экран, `Ctrl+Alt+m` — свернуть, правый `Ctrl` — отпустить захват
клавиатуры и мыши.

## Известные ограничения

* Только RDP. VNC/SSH и прочее — не цель проекта.
* Проброс камеры недоступен: в FreeRDP 3.31 такого флага нет.
* Качество звука задаётся только внутри `/sound` — отдельного флага не существует.
* Одна сессия = одно окно клиента. Вкладок внутри лаунчера нет намеренно: это вернуло бы
  нас к архитектуре, из-за которой страдают Remmina и подобные.
* `xfreerdp` и особенно `wlfreerdp` в интерфейсе доступны, но не рекомендуются: первый идёт
  через XWayland, второй официально заброшен.
